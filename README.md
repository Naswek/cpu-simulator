# Лабораторная работа №4

ФИО: Ровкова Анастасия Сергеевна

Группа: P3216

Вариант:

```text
forth | acc | neum | hw | tick | binary | trap | port | cstr | prob2
```

Усложнение `superscalar` не используется.

## Язык программирования

Реализуется Forth-подобный стековый язык. Программа состоит из слов, числовых
литералов, строковых литералов, определений переменных и определений новых слов.

Синтаксис:

```ebnf
program      ::= item*
item         ::= number | string | word | variable-def | word-def | control
variable-def ::= "variable" word
word-def     ::= ":" word item* ";"
control      ::= if | begin-loop
if           ::= "if" item* ("else" item*)? "then"
begin-loop   ::= "begin" item* ("until" | "again" | "while" item* "repeat")
string       ::= 's"' chars '"'
comment      ::= '\' chars newline
```

Семантика:

- вычисления выполняются через стек данных;
- числовые литералы имеют тип `int32` и помещаются на стек;
- строковые литералы размещаются в статической памяти как c-string;
- имя переменной помещает на стек адрес ячейки памяти;
- `@` читает значение по адресу со стека, `!` записывает значение по адресу;
- пользовательские слова определяются через `: name ... ;` и вызываются по имени;
- определения слов должны идти до основного исполняемого кода;
- комментарий начинается с `\` и продолжается до конца строки.

## Организация памяти

Архитектура использует единую память для инструкций и данных (`neum`).
Размер машинного слова - `4` байта, размер памяти - `2048` байт.
Адреса в инструкциях задаются в байтах и должны быть выровнены по размеру слова.

Доступные программисту сущности:

- стек данных;
- переменные в статической памяти;
- пользовательские слова;
- порты ввода-вывода.

Схема размещения памяти:

```text
0x000 : jmp main
0x004 : interrupt vector 0
0x008 : interrupt vector 1
0x00C : code / word bodies / main
...
high addresses:
        strings
        variables
        temporary translator cells
0x7FC : zero cell
```

Особенности отображения:

- короткие числовые литералы кодируются непосредственным операндом `ld_imm`;
- строковые литералы занимают несколько машинных слов, по одному символу на слово,
  и завершаются нулевым словом;
- переменная занимает одну ячейку статической памяти;
- адрес обработчика `handle_input`, если такое слово определено, записывается в
  interrupt vector для input-порта.

## Система команд

Процессор аккумуляторный (`acc`): арифметические и логические операции используют
`ACC` как левый операнд и записывают результат обратно в `ACC`.

Архитектурные регистры: `ACC`, `PC`, `IR`, `DSP`, `RS`, `SR`, `AR`, `DR`.
Регистр статуса `SR` содержит флаги `Z`, `N`, `C`, `V`, `IE`, `IM`.

Формат инструкции:

```text
31            24 23                         0
+---------------+----------------------------+
| opcode, 8 bit | operand, 24 bit            |
+---------------+----------------------------+
```

Бинарное представление записывается последовательностью 32-битных слов в big-endian
формате.

Виды операндов:

- `none` - команда без операнда;
- `imm` - непосредственное значение;
- `addr` - адрес в памяти;
- `stack_offset` - смещение относительно вершины стека данных;
- `port` - номер порта.

Порты:

| Порт | Устройство |
| ---: | ---------- |
| `0` | input |
| `1` | output |

Такты: все инструкции текущей ISA занимают `1` такт полного исполнения, кроме
`nop`, который занимает `2` такта.

Набор команд:

| Группа | Команды |
| ------ | ------- |
| Служебные | `halt`, `nop`, `ei`, `di`, `iret` |
| Управление потоком | `jmp`, `jz`, `jc`, `jnc`, `jp`, `jn`, `jnz`, `call`, `call_ind`, `ret` |
| Стек | `push`, `pop` |
| Память | `ld_imm`, `ld_addr`, `ld_ind`, `ld_sp_n`, `st_addr`, `st_ind`, `st_sp_n` |
| ALU | `add`, `sub`, `mul`, `mod`, `div`, `inc`, `dec`, `cmp`, `and`, `or`, `not` |
| I/O | `in`, `out` |

## Транслятор

Транслятор реализован как консольное приложение:

```bash
go run ./cmd/translator <input.forth> <output.bin>
```

Входные данные:

- файл с исходным кодом на Forth-подобном языке;
- имя файла для сохранения машинного кода.

Выходные данные:

- бинарный файл с образом памяти;
- файл дизассемблера `<output>.disasm`.

Основные этапы работы:

1. Токенизация исходного текста: числа, слова, строки и комментарии.
2. Построение таблиц символов для переменных и пользовательских слов.
3. Выделение статической памяти под переменные, строки и служебные ячейки.
4. Генерация инструкций ISA через emit-функции.
5. Патчинг адресов переходов, вызовов и interrupt vector table.
6. Кодирование инструкций и данных в бинарный образ памяти.

Пример строки дизассемблера:

```text
0000000C - 2000002A - ld_imm #42
```

## Модель процессора

Модель процессора исполняет бинарный образ памяти, полученный после трансляции.
Схема DataPath и ControlUnit совмещена и находится в `fig/схема_4.drawio.png`.
Сигналы управления на схеме показаны пунктирными линиями, линии данных и адресов -
сплошными.

Основное состояние модели:

- `ACC` - аккумулятор;
- `PC` - адрес текущей инструкции;
- `IR` - текущая инструкция;
- `SR` - регистр статуса;
- `DSP` - указатель стека данных;
- `RSP` - указатель стека возвратов;
- `memoryImage` - единая память команд и данных;
- `IOController` - состояние портов, output buffer и линия IRQ.

Цикл исполнения одной инструкции:

1. контроллер ввода-вывода обновляет состояние по текущему такту;
2. если включены прерывания и поднята линия IRQ, процессор переходит к обработчику;
3. по адресу `PC` читается машинное слово;
4. инструкция декодируется в `IR`, `PC` сдвигается на размер слова;
5. выполняется команда и обновляются регистры/флаги;
6. счетчик тактов увеличивается на стоимость инструкции.

Ввод-вывод реализован через отдельные инструкции `in` и `out`. Входные события
попадают в контроллер ввода-вывода по расписанию, после чего контроллер поднимает
IRQ. При входе в обработчик процессор сохраняет `PC` на стек возвратов, выставляет
флаг `IM` и переходит по адресу из interrupt vector table. Команда `iret` снимает
`IM` и возвращает управление через стек возвратов.

Запуск модели:

```bash
go run ./cmd/machine <program.bin> <input.txt> <max_ticks> <log.txt>
```

Входной файл интерпретируется как последовательность байтов. Для каждого байта
создается событие ввода с фиксированным шагом `10` тактов: первый байт доступен на
такте `0`, второй - на такте `10`, третий - на такте `20` и т.д.

После завершения моделирования накопленный буфер вывода печатается в стандартный
вывод. Журнал работы записывается в файл `<log.txt>` даже в случае ошибки
исполнения, если модель успела выполнить часть инструкций.

Формат строки журнала:

```text
tick=1 pc=0x000000B4 acc=0 sr=0x00 ir=0x100000B4 instr="jmp 0x0000B4" interrupt=false output=""
```
